# Proposed headless 0.4 communication feasibility run

This is a prepared research-only GitHub Actions workflow. It has not been committed, triggered or executed at the time of preparation. It uses no secrets in the code. It is not the installed tablet or an exact execution of the P3.13 Android activity.

The intent is to use the existing `ANTHROPIC_API_KEY` repository secret, if available, within a temporary 0.4 branch's runner; never print or return its value. The workflow runs the 0.4 repository's P3.12 Numogram/PFM Python code and reproduces the P3.12 Kotlin prompt template in Python. It makes Anthropic Messages calls using the P3.13 source's default model, `claude-sonnet-5`, and provider-default sampling. This is **not** a call through the separately identified Railway relay. The source code of the independent Python prompt-builder translation must be available for review.

Twelve previously prepared synthetic cases are tested in fixed case order, with P3.13-style A→B→C order and one request per branch (at most 36 provider calls). The provider receives both user prompts in every arm, so ordinary correct recall cannot establish PFM supplied the information. Compare B retained versus C reset on the same cases, then B versus A absent. Score the first-line letter and preserve the complete responses for blinded relevance/grounding/clarity review. The questions were previously seen by the standalone symbolic component; no P3.13 or other provider response to them has yet been observed. These are exploratory cases, not an independently blinded confirmatory sample. Do not infer independent agency from language quality or an input-dependent answer.

The runner must verify the pinned 0.4 source hashes and the P3.12 matched-transition/memory gate. If the provider rejects a call or a transport error occurs, preserve the attempted record and stop rather than change model, tune prompts or retry selectively. Report all missing/invalid responses. After each complete case, check the Numogram branch-state digest remains unchanged by rendering.

The generated branch and its workflow live in a public repository. The test cases are synthetic and contain no private user text or credentials; action logs and artifacts will be visible under the repository's normal access settings. The 0.4 main branch, existing live app, device data and Railway configuration must remain unchanged. The human user's previously requested 0.4 version remains the target; do not use Orange or substitute the separately active Amelia 1.0 branch.
