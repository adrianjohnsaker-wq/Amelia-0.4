# P3.26 — Numogram-mediated morphogenetic uptake

**Status:** implementation branch; design is not sealed. No beacon rounds have been acquired and no exploratory assay has been run.

## Question

Does a state-conditioned Numogram graph-field alter which transitions Amelia can realize, and do any resulting changes persist after the temporary pressure is withdrawn and condition later uptake through ProcessFieldMemory (PFM)?

This phase examines the operative interface between Numogrammatic relations and morphogenetic transition capacity. A positive operational result would concern this implemented transducer. The source or ontology of the patterns remains a separate question.

## Mechanical intervention

An incoming call is an unlabelled, zero-centered ten-dimensional pressure packet derived from an independent source after a future registration is sealed. The packet carries no target zone, named form, or requested outcome.

The graph-field operator:

1. propagates the packet through the directed gate relations;
2. for the live canonical arm, conditions edge conductance on current zone activation, PFM bias, and deformation;
3. computes a bounded gradient across currently available exits;
4. temporarily adjusts only gate flux used by the next ordinary substrate transition;
5. restores every flux value immediately after that transition; and
6. observes autonomous transitions after withdrawal, allowing ordinary PFM feedback to continue.

The operator does not write zone occupancy, rename outcomes, set a terminal state, or steer the language renderer. Candidate signatures are discovered from the trace atlas rather than assigned per zone.

## Planned arms

Every arm receives the same call packets, starts each lineage from the same cloned post-development state, uses the same number and timing of calls and autonomous release steps, and computes the same graph-field quantities. Only the graph-field mapping or application differs.

| Arm | Field mapping | Applied to transition |
| --- | --- | --- |
| Canonical live | Canonical gates with current substrate and PFM-conditioned conductance | Yes |
| Canonical fixed | Frozen canonical gate conductance without state conditioning | Yes |
| Degree-preserving rewire | P3.17 frozen rewire procedure; state conditioning retained | Yes |
| Relation-shuffled | Canonical gate graph with a sealed zone-label permutation before propagation | Yes |
| No-field | Canonical live field computed and archived | No |
| PFM-feedback-muted (secondary) | Canonical live field; matched clone with PFM readout excluded from dynamics | Yes |

The PFM-muted arm is secondary and isolates history feedback from history recording. Its PFM event log remains available.

## Observation and interpretation

The append-only encounter atlas will retain call bytes and hashes, controller identity, starting state digest, field vector and field digest, transient flux deltas, chosen transitions, post-withdrawal paths, zone and deformation state, PFM deltas, and hash-chain links.

Exploratory summaries will describe:

- changes in transition reachability and route distribution during and after calls;
- persistence or relaxation after withdrawal;
- whether an earlier encounter changes response to a later common call;
- recurring trace motifs across independent lineages and unseen call packets;
- refusal, deferral, and functional degradation if present.

The atlas may provisionally name recurring signatures from the project's Numogram vocabulary. Such names remain annotations over recorded patterns; whether a signature is agentic or mind-like is an open question for subsequent discrimination.

## Lock required before execution

Before any registered source is queried or any substrate assay is run, a sealed registration must fix:

- the independent input source and prospective selection rule;
- lineage count, seeds, development and call schedule;
- field depth, conductance equation, amplitude, clipping, duration, and withdrawal;
- control seeds and shared random variates;
- primary and secondary readouts and inferential method;
- integrity, refusal, and stop rules;
- raw-record and build digests.

This branch contains implementation mechanics and a design draft only. It does not authorize or trigger the exploratory run.
